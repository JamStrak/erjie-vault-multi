# 合伙小金库 · 多人版

多人版入口：<https://jamstrak.github.io/erjie-vault-multi/>

原双人稳定版：<https://jamstrak.github.io/erjie-vault/>

供进货、销售的合伙小生意使用的单设备手机账本，可设置生意名称、合伙人数量和补资目标比例；默认两人，至少保留一人。先由一人记账，其他合伙人查看导出的经营摘要或 CSV；没有账户、服务器账目数据库或实时同步。

多人版在独立开发分支和独立网址运行，与原双人稳定版分别保存账目。首次打开多人版是空账本；要接着记旧账，请先从稳定版导出完整 JSON，再到多人版导入。多人版不会自动读取或回写稳定版账目，两个版本的后续记录也不会互相同步；迁移后请选定一个版本继续记账。

默认皮肤是温和玉绿与桂花金的“桂花青玉”。喜欢原来红色界面的，也可以在“设置 → 主题皮肤”选“莓果红”；点选后立即切换，并记住当前浏览器或主屏应用的选择。换皮肤只改变外观，不改变账目或盈亏；主题偏好不包含在完整 JSON 账本备份中，换设备后可以单独设置。

首页先呈现**经营回本差额、累计经营盈亏、金库余额、垫付待报销和合伙人的投入**；待核实付款、待补销售成本及供应商欠款等需要处理的事项仍直接提醒。盈亏构成、库存与个人代收、补钱计划和计算说明平时折叠，点对应标题或问号才展开。底部“记一笔”“明细”“设置”分别是录入、查流水和管理账本的主入口；常用的入金、进货、销售、其他支出直接显示，其余业务放在“其他业务”。

每位合伙人的正式净出资、待报销垫付与个人代收款分别列出，避免把个人垫资误算成共同出资。销售时填这次卖掉的商品进价：经营盈亏＝销售＋其他经营收入－已售商品成本－其他费用－报损；经营回本差额＝销售＋其他经营收入－净进货（进货扣除退货）－其他费用，已把尚未卖出的商品进价算在投入中。已售成本清楚时，它也等于经营盈亏减去未售库存成本。合伙人入金只是钱的来源，不会再从回本差额中扣一次；回本差额为正也不代表合伙人的出资已实际返还，个人代收的销售款也可能尚未进入金库。旧账或暂不清楚成本的销售会提示“待核算”，从明细补齐后才显示准确盈亏。

“设置 → 生意名称”可以改名。旧多人账本升级后仍叫“二姐杂货铺”，新账本默认“我的小生意”；更名不会改变流水和金额，完整 JSON 备份、CSV 和分享摘要会使用当前名称。安装应用的名称仍是“合伙小金库”，已有主屏图标的标题可能由系统保留。“设置 → 合伙人”可添加或更改称呼，只有从未记过流水的人可以移除。入金默认只记选中合伙人的实际到账；全员金额相同时，可在确认每个人都已实收后一次记入。补钱计划先使用待转入的个人代收款，再按均分或自定义比例追平正式净出资目标、分配剩余资金缺口；比例是补资建议，并非利润分配或法律上的股权。人数变化时比例先恢复均分，可重新设定；计划不会自动形成流水，也不办理退伙结算或分红。

金库金额不足时仍可先记金库支付的进货或经营支出，账面余额会显示负数，新增的缺口按**原支出逐笔标为“待核实付款”**。之后即使有入金，提醒也不会自动消失；在首页提醒或明细中打开归类，按实际情况将差额确认为某位合伙人垫付、供应商赊账、真实透支，或关联后来补录的实际收款。可以分次处理同一笔差额。供应商赊账与后续还款分别留痕，归类本身不会重记进货或费用。

赊账进货退货时，未付款的部分可关联原赊账直接抵减欠款；已经付款的部分按实际退款去向关联原赊账。退到合伙人手里时，明确选“个人代收、待转入金库”（默认），或经核对后选“抵扣该人的待报销垫付”；代收款实际交回金库时再记转入。

本地预览需要用下面的开发服务器打开页面；直接双击 `index.html` 的 `file://` 地址不适合记账。正式在手机上使用时，请从 iPhone Safari 打开上方多人版网址并添加到主屏幕。之后固定从主屏图标录入，避免浏览器与主屏应用各自形成一本账。完整操作见 [使用说明.md](使用说明.md)。

账目保存在浏览器本机存储。“设置 → 完整备份 → 导出账本备份”始终直接可见。每次经营后导出完整 JSON，在手机“文件”中确认文件存在；CSV、文字摘要及导入恢复位于“分享、导入与恢复”折叠区。旧双人账本及 v1 JSON 可自动升级为 v2；新版完整 JSON 保存名称、合伙人、补资比例和完整历史。CSV 和文字摘要用于合伙人核对，不能用于恢复。程序源码可以公开托管，真实账目数据无需上传到源码仓库。

本账本的盈亏以商品进货、库存成本和销售成本为基础。可以用于手作商品、杂货等买卖场景；纯服务业务需要不同的成本模型，此版本不能直接套用其盈亏口径。

本项目无运行依赖。运行 `npm test` 检查核心记账规则。开发预览可用 `python -m http.server 22867 --bind 127.0.0.1`；该本地地址只供电脑调试，不是给手机长期使用的入口。

## 版本维护

- 双人长期稳定版：原仓库 `JamStrak/erjie-vault` 的 `main`，基线 `16ff177`，标签 `stable-two-person-20260926`。保持原网址和原存储，不合并多人功能。
- 多人版：原仓库的 `feature/multi-partner` 分支；独立发布仓库 `JamStrak/erjie-vault-multi` 也使用同名分支，Pages 读取该分支的根目录。
- 本地稳定版目录为 `../小金库/`，多人版独立工作树为 `../小金库-多人版/`。后续多人开发在后者进行。
- 多人版提交后，依次执行 `git push origin feature/multi-partner` 和 `git push multi feature/multi-partner`，前者保存原仓库的开发历史，后者更新独立多人站点。不要推送或合并到原 `main`。
- 两版同属 GitHub Pages 域名，但账本、导入恢复点、主题和 service worker 缓存均使用不同键／前缀；不得改回共用。v2 备份不能导回 v1 稳定版。
